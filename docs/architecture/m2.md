# M2 virtual processes, floating point and terminal

M2 executes selected static AArch64 musl/BusyBox programs through the Rust
reference interpreter. Guest fork and exec do not invoke a host process. Source
code is unchanged upstream code; no outputs are substituted by executable name.
There is still no JIT, dynamic loader, native guest-library interception or
third-party Rust dependency.

## Floating point

`soft_float` implements binary32 and binary64 using integer significands and
exponents. Guard, round and sticky information survives arithmetic until the
single rounding step. The implementation does not depend on the host's floating
point rounding environment. It covers add/subtract, multiply/divide, square root,
fused multiply/add forms, min/max and numeric min/max, compare/conditional
compare/select, format and signed/unsigned integer/fixed-point conversions,
round-to-integral instructions and scalar/GPR bit transfers, including upper D
lanes. SIMD support adds packed S/D arithmetic, fused operations, comparisons,
integer conversions, rounding, pairwise addition and floating immediates.

FPCR models four rounding modes, flush-to-zero and default-NaN. FPSR accumulates
invalid, divide-by-zero, overflow, underflow, inexact and input-denormal flags.
Signed zero, infinity, quiet/signaling NaNs and payload propagation are covered
by differential tests. Exception-trap enables are RAZ/WI; no hardware exception
trap extension, FP16 arithmetic, SVE or complete AdvSIMD coverage is advertised.
Unsupported encodings still fault. The remaining estimate/refinement and other
unimplemented SIMD instruction families do not become native host operations.

AdvSIMD multiple-structure loads/stores cover LD1/ST1 and interleaved LD2/3/4
and ST2/3/4, including post-index and register wrap. Complete buffers are checked
before changing any destination, memory or writeback base.

## Processes and execution

The core has a cooperative virtual process table. A runnable process executes
at most 4096 instructions before another process can run. PID, PPID, process
group and session IDs are private to the runtime; the session root has PID 1
and ordinary shell signal defaults. Fork-style AArch64 clone creates a child
with independent CPU state and copy-on-write memory pages. Processes share VFS
inodes and open-file descriptions, including file positions and status flags;
the descriptor table, CLOEXEC flags, cwd and umask are copied independently.
Threads, shared-VM clone and vfork are rejected rather than approximated as fork.

`execve` reads an executable from the VFS, validates a fresh static ELF and
initial stack before replacing the process, closes CLOEXEC descriptors and
resets caught signal dispositions. Ignored dispositions and the signal mask
survive. Byte argv/envp and bounded shebang interpreter chains are supported.
Failed exec leaves the previous image and descriptors intact. The CLI's explicit
`--exec-file` marks an imported copy executable; `--install-busybox` installs
hard links to the supplied real multicall ELF. These links are ordinary VFS
entries and follow normal ELF execution.

`wait4` reports exit/signal/stop/continue status, supports WNOHANG, and reaps
children. Ignored SIGCHLD and SA_NOCLDWAIT auto-reap children. Exit closes the
process's descriptors and releases child memory; session-root exit cancels
remaining virtual children. There is no daemon surviving the runtime session.

## Blocking IO and signals

Pipes have 64 KiB buffers and PIPE_BUF=4096 atomic small writes. Full writes and
empty reads suspend the process; other virtual processes continue. EOF follows
the last shared writer's close. A missing reader returns EPIPE and generates
SIGPIPE. Nonblocking descriptors return EAGAIN. dup/dup3 and fcntl duplication
share descriptions without sharing per-descriptor CLOEXEC. Poll/ppoll and
select/pselect test virtual descriptors and support timeout and temporary masks.
Nanosleep/clock_nanosleep use host monotonic deadlines; realtime queries use the
host clock. These are explicit adapters, not guest-selected host syscalls.

Signal actions, masks, pending standard signals, kill/tkill/tgkill, suspend,
stop/continue and rt_sigreturn are modeled. Delivery constructs an AArch64
Linux signal frame with siginfo, ucontext, registers, PSTATE/NZCV and FPSIMD
context. Signal return validates and restores the guest-modifiable context.
SA_RESTART restarts read/write/writev/wait; other interrupted waits report EINTR.
A stopped process retains its blocked operation or sleep deadline. SIGKILL has
priority and cannot be blocked. Alternate stacks are explicitly unsupported;
realtime queuing, timers, ptrace and full Linux signal behavior are not claimed.

## Virtual PTY

`Runtime::enable_terminal` attaches one virtual slave to descriptors 0/1/2 and
`/dev/tty`. Its master is the embedding application's byte-stream interface,
not a host tty passed through to guest syscalls. Basic canonical/raw input,
erase/kill/EOF, ISIG controls, echo, ONLCR, IXON, window size and foreground
process-group ioctls are modeled. Background reads use SIGTTIN; terminal-setting
changes and TOSTOP writes use SIGTTOU. Nonzero VTIME returns EOPNOTSUPP.

The master accepts Resize and Signal events through `GuestOutput::terminal_event`.
Resize updates the virtual window and signals the foreground group with SIGWINCH.
`Terminal::drain_output` retains access to queued output after session exit.
The current Linux CLI sets its host input terminal raw with `stty` and restores
settings on normal return; it uses a bounded input worker and flushed byte output.
Its virtual size defaults to 24x80; automatic host resize and multiple guest PTY
pairs are follow-up work. A Swift frontend can supply master events directly.

At M2 acceptance, persistence and file budgets were unchanged at the owner's
request. The subsequently authorized [storage follow-up](storage.md) adds disk
files, an initial 16 GiB logical budget, volume-capacity snapshots and stream
interfaces. No 16 GiB RAM allocation is introduced. Native iPad Files UI remains
future work. See [security limits](../security/README.md) and the
[validation record](../validation/m2.md) for measured scope and remaining gaps.
