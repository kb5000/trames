## File creation failure

Before the fix, reopening the same Python store with 1,476 private file objects
worked under Linux's normal descriptor limit and failed with VFS errno 5 (EIO)
under RLIMIT_NOFILE=256. Source inspection confirmed one permanently open native
file per persisted inode. After the fix, the same current-format data opens under
128 descriptors. The test changes only child-process limits, not the test server
or the whole Rust test process.

`tests/integration/python.py` installs upstream signed Alpine Python and its
actual pycache payload in a fresh store under 128 descriptors, reopens it, repairs
`python3` and `python3-pycache-pyc0`, and executes Python imports/math/JSON/sqlite3.
It checks the exact reported `pty.cpython-312.pyc` path and an unrelated data file.
Creation/reopen/repair use actual apk and guest binaries, without guest wrappers.
This is selected Python coverage, not acceptance of all Python packages or M6.

The owner subsequently chose to clear development data. Historical manifest and
old-default configuration migrations are removed. Tests check unsupported-format
rejection without deletion, normal v3 persistence, explicit reset refusing live
stores and successful deletion after the asynchronous worker releases its lock.

## Bridge and native resources

Rust tests cover byte fragmentation/coalescing, malformed/oversized frames,
unknown methods, duplicate IDs, limits/backpressure, connection/session isolation,
claimed replies, explicit null results, cancellation, expiry and late replies.
VFS tests check the actual volatile device, shared dup state and ESPIPE.
The C ABI integration test runs the real Alpine `trames` CLI, delays native replies,
returns denial/allow results, rejects stale replies and exercises built-in SHA-256
while disabled/enabled/disabled. Existing PTY, transfer, cancellation and reopen
checks remain in the same integration suite.

Native Swift checks cover uint64 ticket precision, strict bounded parameters,
HTTP/HTTPS validation, traversal/symlink rejection and revocation. macOS adds
coordinated exclusive/bounded copies and bookmark persistence/revocation. The
simulator suite adds visible guest consent and actual gateway DNS/HTTPS apk.
Bootstrap retry tests cover transient permission/connectivity recovery, bounded
attempts, permanent errors and cancellation without another read. Acceptance of
the initial iPad network-permission prompt still needs a physical device.
Third-party provider behavior, signed-device clipboard permissions and physical
DNS failure still require owner verification.

## CPU and profile

New SIMD differential cases cover lane copies/duplication, TBL/TBX boundaries and
register wrap, vector shifts (signed/unsigned, rounded, accumulated, inserted),
permutations, narrowing and integer arithmetic. Structure load/store coverage
includes single lanes, replication, multiple structures and writeback/register
wrap. Full existing QEMU suites are run with reference and optional C++ backends.
ASan/UBSan runs 100,000 bounded native calls for computed-goto and portable dispatch
and compares checksums. Linux's managed ptrace environment requires disabling
LeakSanitizer locally; address/undefined-behavior instrumentation remains active.
CI uses the normal sanitizer configuration.

The CPU-only profile asserts equal final register/memory state on an integer loop
and a load/store loop. It records backend, instructions, elapsed seconds and IPS.
It is a Linux software profile, not iPad app performance. Integer batching can
improve throughput; fallback-heavy memory work can be slower. Rust stays default.
Measured local samples are below; final CI and artifact evidence is recorded above.

Local CPU profile (three runs, 2026-10-11): Linux x86_64, Intel Xeon Platinum
8573C, Rust 1.90.0, GCC 14.2.0 C++17; Cargo release opt-level 3, thin LTO and
overflow checks, `cpp` feature, computed-goto dispatch. The 12,000,000-instruction
integer loop has median elapsed times 0.548 s (Rust) and 0.0577 s (C++); the median
of the three paired speed ratios is 5.61. The 1,000,000-instruction load/store loop
has median times 0.0620 s and 0.0618 s, with median paired ratio 1.00. The launched
child process high-water RSS is 11,392 KiB. Every run asserts equal final CPU and
memory state. Short loops on the shared cloud host show scheduling variance;
these numbers are not app RSS, general application speedups or iPad measurements.
[Raw samples, platform and flags](m5-profile-linux.json) preserve that variation.
CI separately uploads its CPU-profile and sanitizer records for both matrix jobs.

The first Linux CI reference job exposed a QEMU-oracle fixture assumption: it
read a descriptor number after a worker closed it, expecting EBADF. Native QEMU
helper threads can reuse that number. The fixture now checks EPIPE on the other
end of the pipe after the last reader closes, retaining the shared-FD-table
assertion without depending on descriptor-number reuse. The runtime is unchanged.
