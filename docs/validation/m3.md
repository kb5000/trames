# M3: dynamic musl, Alpine and authenticated apk

Pinned upstream Alpine 3.22.6 AArch64 minirootfs is imported into the actual VFS;
its BusyBox, musl, OpenSSL, libfetch and apk binaries are unmodified. The
integration script uses a native loopback HTTPS server serving an unchanged
Alpine-signed main repository index and the pinned tree 2.2.1-r0 package. It
does not replace guest TLS, forge Alpine signatures or use --allow-untrusted /
--no-check-certificate. A per-test CA is explicitly trusted for the local test
server, with matching hostname and certificate; Alpine package keys come from
the pinned rootfs.

Reproduce after the static musl toolchain is prepared:

~~~sh
cargo build --workspace --locked
cargo build --release --workspace --locked
bash scripts/prepare-alpine.sh
python3 tests/differential/widening_integer.py
python3 tests/integration/m3.py
cargo check -p trames-core -p trames-distro --target aarch64-apple-ios --locked
~~~

Validated locally: 36 new QEMU program/scenario comparisons, 72 widening SIMD
snapshots in one additional comparison, and 89 workspace unit tests. Existing
network (36), storage (2) and M2 memory/disk (24 each) regressions pass. Core and
distro pass the iOS target compile check; no SDK link or device test is claimed.

The suite compares dynamic PIE and fixed ET_EXEC fixtures with QEMU in both
memory and disk backends: dlopen/dlsym, DSO TLS across fork, private file mmap
at nonzero offset, unchanged fd offset/backing file, protection/unmap, invalid
MAP_FIXED backing fd without data loss, symlink/readlink/O_NOFOLLOW/unlink,
blocking/nonblocking flock across fork, and nondeterministic getrandom.
Upstream BusyBox and apk output/version comparisons cover dynamic distro
execution. SSH and generic glibc compatibility are not established.

The HTTPS path performs apk update, apk add tree=2.2.1-r0, executes the real
BusyBox trigger script in virtual fork/exec, reopens the disk store, and runs
the installed tree binary for version and directory listing. QEMU uses the
identical CA and repository for independent TLS/signature/installed-program
checks. Only its native apk installation disables scripts, because QEMU user
mode has no Trames guest exec supervisor; Trames executes the real trigger and
must produce no error or warning.

Both engines must reject an untrusted CA, a trusted certificate with the wrong
hostname, a structurally valid index with a corrupted RSA signature, and a
structurally valid package with a corrupted RSA signature. Failed package
installation must leave the tree package unregistered and preserve the original
BusyBox tree alias. A modified rootfs archive is rejected
by its pinned SHA-256 before namespace import. Tests do not disable the executor
proxy or make public direct TCP connections. Public artifact downloads use the
configured HTTPS path; guest end-to-end HTTPS is deterministic loopback.

The SIMD SSHLL/USHLL family, used by upstream musl poll, is compared with QEMU
across signedness, 8/16/32-bit source lanes, lower/upper halves, 0/1/maximum
shifts and destination aliasing: 72 register snapshots in one comparison.

M3 completion establishes these selected real distribution workflows. It does
not establish every Alpine package or syscall, MAP_SHARED/page-cache coherence,
SIGBUS beyond EOF, arbitrary archive import, a signed iPad app or device network
validation. Current rootfs versions and package dependencies are pinned test
inputs; the signed repository index can advance and remains authenticated by apk.
