There are 427 program/scenario QEMU comparisons, plus 9 interactive assertions.
The four standalone fault/host-scope checks remain in addition to the unit
boundary tests. FP results are compared as bits together with FPSR (and scalar
NZCV), across rounding modes, FZ/DN, random values, signed zeros, subnormals,
infinities and quiet/signaling NaNs. The same unchanged pinned musl/BusyBox build
executes on both sides. QEMU uses cortex-a53 for a matching base ARMv8 model.

The process fixture checks fork isolation, shared file offsets, 256 KiB pipe
backpressure/EOF, signal masks/context return, SA_RESTART, stop/continue status,
poll/select, exec argv/envp/CLOEXEC, EPIPE and ignored-SIGCHLD reaping. The math
fixture compares sqrt, sin, cos, exp, log, pow, fma, hypot, formatted output and
rounding-environment results. The PTY fixture checks a prompt, editing, pipeline,
Ctrl-C status 130, Ctrl-Z/jobs, bg, fg interruption and Ctrl-D exit.

QEMU user mode cannot recursively exec foreign ELF on every CI host without
binfmt registration. Reference external applets therefore use small host exec
wrappers that immediately re-enter QEMU with the same AArch64 BusyBox or probe.
The Trames side loads the actual guest ELF through virtual execve. Wrapper paths
are supplied through the reference PATH; reference subprocess IDs are not compared.
Only the known reference cwd prefix is normalized for the cwd test. Output bytes,
errors and exit statuses otherwise remain exact. Interactive tests compare
explicit semantic outcomes rather than nondeterministic prompt scheduling.

Unit boundaries include shared descriptions vs independent CLOEXEC/cwd, the
last pipe endpoint, atomic small writes, open-unlinked quota lifetime, COW page
permissions, failed exec, malformed signal frames, restart/EINTR, stopped timers,
SIGKILL priority, process limits, terminal packet/echo limits and resize scoping.

This does not establish complete AArch64/SIMD, FP16/SVE, all libm operations,
threads/shared-VM clone/vfork, blocking futex, alternate signal stacks, multiple
PTY pairs or nonzero VTIME. The selected BusyBox configuration is still narrower
than a distribution build. Dynamic linking/Alpine, networking, persistent disk
storage, native SSH and iPadOS remain future work. No performance claim, audit,
broad fuzz campaign, sanitizer run, C++ backend or actual iPad test is included.

Reproduce with the commands in README, using scripts/build-m2-fixtures.sh after
building musl/BusyBox. The pinned archives, build flags and license obligations
are described in [busybox.md](../testing/busybox.md).
