# NativeCall worker concurrency

Development follow-up to [coherent native backing](bulk-native.md), tracked in
[Issue #16](https://github.com/kb5000/trames/issues/16).
Baseline: `a0648eb00941745c59b3c94b25f7deaca0877bc5`, archived and independently
built in release mode before edits. [Architecture](../architecture/parallel-nativecalls.md)
defines worker ownership, typed private-file deferral and exact HLT accounting.
The already delivered 0.13.0/build 14 IPA remains unchanged.

All 19 pure entries, integer/floating parsing and guest-owned qsort/bsearch steps
can now execute on persistent workers without stopping independent peers. No
guest callback becomes a host pointer. Scoped page locks preserve dirty fragments,
exclusive reservations and executable code versions. Kernel/VFS/mapping effects
and undetached private file accesses still use coordinated checkpoints.

## Correctness

Unit tests compare Memory/View results and bytes for all 19 entries, exercise
directional and physical-alias moves, shared aliases/fork COW/code tokens, stable
lock ordering and lazy reservation epochs including wrap. A deterministic worker
test holds one native operation's page while another worker completes its own
native body and syscall, requiring observed overlap of two native scopes.
Retirement tests cover success/fallback exactly once, fault credit refund,
pending private-file HLT reservation without writes, precise registers/faults
and unstable five-word code observations that never enter or cache the body.
Resumed sorts recheck the array before cycle writes after a comparator syscall.

The real musl pthread fixture checks all 19 entries, per-thread FPCR/FPSR and errno,
integer/floating parsing, nested qsort and bsearch against original musl under
independent QEMU. Off/on, 1/2/4 CPUs, shared guest stacks and persistent storage
are covered; short-call peak overlap is diagnostic rather than a flaky assertion.
Linux CI additionally runs native worker/core/memory tests as actual ARM64 binaries;
Apple CI runs these tests on native Apple ARM64 and verifies the simulator report.

Local validation passes 254 workspace tests and 199 selected actual ARM64 tests
under QEMU, strict Clippy and the iOS compilation check. Full-musl startup,
callbacks/persistence and the existing SMP 1/2/4 CPU comparisons also pass.
The final numeric/stdlib regressions cover 712 original-musl floating cases and
476 exact integer rows, including signals/fork/nested callbacks and memory/disk.
[Pthread report](parallel-nativecalls-pthread.json), [transcript](parallel-nativecalls-integration.txt),
[SMP transcript](parallel-nativecalls-smp.txt) and [check fingerprints](parallel-nativecalls.json)
retain local evidence. Exact-source CI/artifact verification is recorded below;
this batch does not claim physical iPad acceptance.

## One fixed-work performance batch

[Raw samples and fingerprints](parallel-nativecalls-benchmark.json), generated by
`tests/performance/native-parallel.py`: three alternating baseline/current samples
at 1/2/4 CPUs, identical new full musl and guest ELF. Four guest threads each copy
a private 1 MiB buffer 128 times and periodically compare it: 512 MiB copied plus
checksum/comparison/startup work. All results match original-musl QEMU. One
unchanged application control sorts 2,048 rows using Alpine BusyBox at one CPU.

| Workload | CPUs | Before, median s | After, median s | Before/after |
| --- | ---: | ---: | ---: | ---: |
| Four-thread native copy | 1 | 0.07364 | 0.08987 | 0.82x |
| Four-thread native copy | 2 | 0.36884 | 0.13314 | 2.77x |
| Four-thread native copy | 4 | 0.42963 | 0.12964 | 3.31x |
| BusyBox sort, 2,048 rows | 1 | 0.40758 | 0.41123 | 0.99x |

Four-CPU native overlap is 4 in every measured current sample. Checkpoints drop
from 452–478 to 25–32; 2-CPU checkpoints drop from 420–526 to 27–29. Both runtimes
transport the same direct bytes without a full copy staging buffer. The improvement
removes global per-call joins and sharply reduces dispatch/commit cost.

The current four-CPU copy result remains slower than the current single-CPU
direct path (0.69x), and adding two more CPUs yields only about 1.03x over two.
Worker page locking, preflight, periodic dirty commit and bandwidth are residual
costs. The one-CPU copy median regresses by 22%; raw current samples range
0.072–0.091 s and baseline samples 0.071–0.075 s, so this batch cannot attribute
that change solely to scheduling noise or dismiss it. BusyBox sort is essentially
flat. No overall single-thread application speedup is claimed.

Runtime seconds exclude rootfs import. Separate host wall/user/system CPU include
startup and import; `cpu_seconds` is summed worker elapsed including lock waits,
not host CPU utilization. This is the x86_64 development interpreter with a
four-core cgroup quota; it measures ARM64 guest execution without measuring NEON
host speed. It is not physical-iPad timing or a general 4x scaling claim.
