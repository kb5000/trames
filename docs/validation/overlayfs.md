# Guest overlayfs / Docker overlay2 acceptance

The development branch adds guest `overlay` mounts and recommends original
Docker's `overlay2` graph driver. No host Docker engine, privileged host mount,
host filesystem namespace or Docker socket is involved. Released 1.0.0 IPA and
main/tag are unchanged.

## Local evidence

- 15 focused overlay tests: merged precedence/type masking; lazy content copy-up;
  old file/proc FD/mmap data references; metadata and hard links; unlink and
  whiteouts; nested whiteout parents; opaque recreation and upper-only rename;
  readonly mount/remount; bind/namespace identity; upper/work leases and lazy
  detach; quotas, O_TRUNC without discarded-data allocation, failed manifest
  rollback; user/trusted attribute selection; inotify and disk reopen.
- Affected VFS/Linux/Core/FFI/CLI clippy passed; inotify 3, proc/pseudo 8 and
  Linux file ABI 3 passed after their final changes. Base VFS results were reused;
  host-socket tests initially blocked by the shell sandbox were rerun with local
  socket access and passed. Unchanged CPU/UI/GPU/network acceptance was not rerun.
- Original signed Alpine 3.22.6 aarch64, Docker 28.3.3-r5, containerd 2.1.5-r2,
  crun 1.23.1-r0. Development run: 4 vCPU, GOMAXPROCS=1, 325.740 seconds.
  Probe, import, run, no untouched BusyBox in upper, diff, commit, committed image
  deletion/hardlink/symlink checks, base-image write isolation, daemon restart
  recovery and cleanup all passed.

The local Docker binary is the recorded development build; final-source Linux
and Apple/iOS CI below supersede it. Raw output and rootfs/APK/binary fingerprints
are in [JSON](overlayfs.json). The fixture optionally retains a private test
store through `TRAMES_OVERLAY_STORE` so failed assertions can be resumed without
reinstalling tools or repeating completed container creation/import.

## Final-source CI

[Apple/iOS](https://github.com/kb5000/trames/actions/runs/39106082144) passed on
source `8f5872a156f05c3fd21eb307d354184ea4aa3fcd`: VFS 139 passed / 1 ignored
(platform count), including all 15 overlay tests, Linux file ABI 3 passed, and
`aarch64-apple-ios` FFI check. [Linux run 39106082142](https://github.com/kb5000/trames/actions/runs/39106082142)
passed: VFS 140 / 1 ignored, all 15 overlay cases, file ABI 3 and original Docker
six-scenario overlay2 workflow (4 vCPU, 455.230 seconds). Artifact #12128587219 (14546 bytes) ZIP SHA256:
`a785fdd7fc594529a458b8924d19a7d6498c769c19ba17c259256db910324a76`.

A final review corrected proc-FD reopen semantics: proc follows the overlay
path and opens a new description using the current layer; dup/fork retain the
old lower-backed description. Linux v6.12 `fs/proc/fd.c:proc_fd_link` and
`fs/overlayfs/file.c:ovl_open` select this behavior. The exact production delta
and unchanged pre-test overlay implementation are checked before reusing full
storage/Docker/platform evidence. Local affected proc tests 15 and clippy passed;
Final runtime source `31abd3538994e501cb249601c2adcca2b8bc608a` passed
[Linux](https://github.com/kb5000/trames/actions/runs/39107028366) and
[Apple/iOS](https://github.com/kb5000/trames/actions/runs/39107028392): affected
proc cases 15 on each platform, VFS clippy and iOS FFI. Full overlay/Docker and
platform IO checks were reused; the workflow verified the exact production
patch SHA256 and unchanged overlay implementation before selecting this scope.
Final evidence-only commit uses `[skip ci]`; runtime/fixtures stay unchanged.
The hash-bound `container-storage` scope runs affected storage/file ABI checks,
with unchanged CPU/UI/GPU/guest libraries and full network evidence reused.
No IPA is generated by this scope. The first Linux workflow accidentally also
included unchanged GTK/foot checks because their exclusion list omitted the new
storage scope. Both passed; the conditions are corrected in the final records
commit. Verified unchanged-source checks are reused rather than rerun.

## Reproduce

```sh
cargo test -p trames-vfs --lib
cargo test -p trames-linux --lib file_calls
cargo build -p trames-cli --release --locked
python3 tests/integration/docker-overlay.py
```

The fixture uses `--network none` and ordinary Docker IPC/cgroup/seccomp/device
isolation; bridge/firewall/NAT acceptance is separate [network evidence](docker-network.md).
This is not acceptance of Registry pull, all volumes/exec/build/Compose workflows,
rootless, full cgroup controllers or containerd's full overlayfs snapshotter.
