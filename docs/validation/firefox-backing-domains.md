# Firefox：减少并行快照的无关文件扫描

2026-10-20，继续[四核页面加载调查](firefox-redirect.md)。宿主叶 PC 采样定位到
`Memory::update_parallel_snapshot` 及文件页版本查询：任意文件或 SHM 修改推进
全局 backing epoch 后，每个 VM 都会重新检查全部文件映射页。此前已经避免了
未变页的重建，但没有避免逐页查询。Firefox 的大型 ELF 映射放大了这项协调成本。
叶采样用于定位热点，不能当作墙钟占比或整机加速比。

现在版本化 provider 可声明稳定的变更域及代数。VFS 以实际 inode 的映射数据为域，
文件写入、截断、原生映射写入和 joined worker 发布推进该代数。增量快照保存
域到虚拟页的索引；全局通知后每域检查一个仍有效的映射，未变文件整组跳过。
变更文件仍逐页比较版本和 EOF，未知 provider 保持原来的保守行为。
截断在实际长度改变后立即通知；后续页重载即使发生 I/O 错误，也不会漏掉已发生的变化。

索引仅保留整数身份和地址，不延长文件或页的所有权。取消映射、替换地址、复用
root-frame 槽时同步维护索引；新增别名不能把旧页尚未处理的文件修改标为已处理。
保留外部旧 View 时继续走完整不可变快照路径。CPU/原生字节访问、COW、权限、
原子和屏障协议没有改变，也没有给普通 CPU 写入增加元数据操作。

小范围回归使用大量只读 ELF 页、一个私有 COW 别名和独立显示缓冲区。连续修改
显示缓冲区时，新增的逐页检查数量断言在旧扫描实现失败，改动后通过；继续验证
代码修改失效、截断 SIGBUS、重新增长和 COW 保留。另补取消代表页映射、不同文件
复用地址、移除域最后成员以及保留旧 View 的回归。

Linux Release 检查：Memory 92、映射 VFS 12、CPU 43、Accelerator 25、Core 88
通过；手工性能测试继续忽略。其余 VFS 检查的五个 socket 用例在默认工具沙箱中
受限，单独给予网络访问后全部通过。严格 Clippy、fmt 和差异检查通过。
本轮没有新的 Apple ARM64/16 KiB 或 iPad 验收；没有重跑无关图形/UI 检查。

四核、低刷新率诊断组已完成目标 HTML、JavaScript 标题和完整绿色 canvas 验收。
使用原版 ARM64 Firefox 142、默认内容沙箱和 Wayland proxy，总/单进程各 4 GiB；
网络及 GPU 关闭，宿主为 Linux，未修改浏览器 ELF。首次组结束阶段的额外 guest
诊断超时；完成截断通知边界补强后，最终 Release 构建复测页面再次通过，结束诊断
也完整。没有把诊断偏好改为产品默认，
也不将单次页面成功解释为联网、GPU、交互或 iPad 可用。

默认刷新率的四核采样组观察 300 秒，仍没有目标脚本标题或绿色 canvas，结束诊断
完整。该组后半程的主热点已从全量文件版本扫描转到解释器指令、向量/浮点执行及
VFS 路径查找，增量快照仍有进一步优化空间。它与旧低刷新率采样组配置不同，
不计算跨组加速比，也不把页面未完成归结为某个尚未确认的单一原因。
