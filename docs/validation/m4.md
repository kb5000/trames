# M4 validation and remaining acceptance

M4 frontend software and unsigned Apple builds are validated at code revision
`395aee87d3b2066d892f09b0cc2a0f77bb73f627` on 2026-10-10. On 2026-10-11,
the owner confirmed signing/installing 0.1.0 using Windows and Sideloadly and
launching it on a physical iPad. The remaining physical checklist is open, so
M4 is not yet accepted as a whole. GitHub's macOS runner supplies Apple SDK builds and simulator testing;
a local Mac is not required for these software checks.

Final CI evidence:

- [Linux runtime](https://github.com/kb5000/trames/actions/runs/38073825926)
  passed the complete Rust, QEMU differential, disk, native/virtual network,
  dynamic Alpine HTTPS/apk and embedding regression suite.
- [Apple frontend](https://github.com/kb5000/trames/actions/runs/38073825975)
  passed native Swift/OpenSSH tests, both unsigned Apple builds and the actual
  simulator test. Its uploaded `ipad-smoke-summary.json` independently records
  `result: Passed`, one passed test, zero failed and zero skipped tests.

Local Linux evidence:

- 103 Rust workspace tests passed; clippy and iOS embedding target check passed.
- Eight Swift tests passed on Swift 6.0.3 Linux: config/pins, SFTP parser and
  real OpenSSH Ed25519 authentication plus a 1 MiB SFTP roundtrip (no PTY).
- Cancelling an endless real SFTP download removes the partial native file and
  preserves the SSH terminal. Reply floods terminate with an explicit error.
- SFTP handshake and complete request deadlines cover stalled writes as well as
  reads; cancellation closes the affected child channel. Native pipeline handlers
  are retrieved and mutated on their owning NIO event loop.
- The C ABI runs the actual pinned Alpine ash interactively: ANSI color bytes,
  37x103 PTY resize, 1 MiB disk import/export equality, exclusive export,
  pause/resume, cancellation during a busy shell and reopening the same store.
- The pinned rootfs hash rejects a tampered initial installation.
- Root exit preserves 100,000 bytes of queued terminal output; transfer tickets
  cancel before dispatch, and bounded key/config exports reject oversized files.

Apple execution evidence:

- macOS 15.7.9 and Xcode 16.4 linked unsigned arm64 iPad simulator and device
  applications. The app links the Rust archive statically; no external Rust
  dylib is required.
- Eight Swift tests passed against a real OpenSSH daemon: host-key pinning,
  SSH config, bounded SFTP framing, native Ed25519 authentication, PTY resize,
  exclusive 1 MiB upload/download and active-copy cancellation with a usable PTY.
- The iPad Pro 11-inch (M4), iOS 18.5 arm64 simulator ran
  `testLaunchAlpineRotateExitAndReopenPersistentStore`: initial Alpine download
  and installation, interactive shell, landscape rotation, Ctrl-D exit, closing
  the last tab and reopening the persistent environment through session actions.
  The test passed in 22.532 seconds; its transcript ends with `TEST SUCCEEDED`.
- CI uses explicit Bash pipefail semantics and also rejects an xcresult summary
  containing failures or no passed tests. Simulator boot and test execution are
  bounded. Session actions use a regular button and native confirmation popover;
  unchanged capacity snapshots do not repeatedly publish UI updates.

First device feedback (2026-10-11):

- The owner confirmed successful Sideloadly installation and startup.
- During `apk add vim`, older terminal content shifted horizontally and its left
  edge became clipped; the cursor reached the bottom/right while new lines were
  unaffected. The exact device event has not been independently reproduced.
- Version 0.1.1 constrains the UIKit terminal to vertical scrollback, fits content
  width to its viewport, keeps horizontal offsets/bounds origins at zero and
  invalidates the visible drawing region after rejected horizontal adjustments.
  It preserves SwiftTerm's vertical scrolling and terminal grid resize behavior.
- Headless replay through the pinned SwiftTerm parser preserves old/new line
  prefixes and cursor save/restore. It follows apk-tools' actual ESC 7 / full-width
  progress / ESC 8 / CSI 0 K sequence, including byte-fragmented UTF-8 block glyphs.
  UIKit tests also cover horizontal adjustments, wide output, rotation and
  keyboard-sized/fractional view resizes. Owner verification of 0.1.1 is pending.
- Code revision `553f163070cbfc0e0c686bb5661efedc142d7e70` passed
  [Linux CI](https://github.com/kb5000/trames/actions/runs/38125137153) and
  [Apple CI](https://github.com/kb5000/trames/actions/runs/38125137163).
  The downloaded simulator summary and transcript independently confirm all
  four viewport regressions plus the launch/reopen test: five passed, zero
  failed, zero skipped. The byte-fragmented actual apk progress case passed.
  The downloaded [0.1.1 IPA](https://github.com/kb5000/trames/actions/runs/38125137163/artifacts/11696719206)
  was checked for iPhoneOS arm64, stable bundle ID, executable permissions,
  checksum and byte-for-byte agreement with the actual device build.
- The owner requested batching future feature work into a larger release; the
  viewport fix will be included. New Linux device feedback covers pseudo-filesystem
  endpoints, `ps`/`mount`/`df`, `ping`/`ip`, apk directory permission updates and
  Vim timer initialization. The 0.2.0 follow-up now executes these actual tools
  and default Vim successfully in software tests; [Linux validation](linux-compat.md)
  records the scope. Acceptance on the owner's iPad is still pending.

Remaining iPad acceptance:

The combined [0.2.0/build 3 update](https://github.com/kb5000/trames/actions/runs/38134473648/artifacts/11700379801)
passed [Linux CI](https://github.com/kb5000/trames/actions/runs/38134473671) and
[Apple attempt 2](https://github.com/kb5000/trames/actions/runs/38134473648/attempts/2).
Its downloaded report confirms five tests passed without failures/skips; all 36
packaged files match the device app, stable bundle ID and checksum were verified.
Linux command/permissions/default Vim evidence is in [linux-compat.md](linux-compat.md).
Apple attempt 1 exposed an intermittent native NIOSSH close/window trap; it is
tracked in [issue #9](https://github.com/kb5000/trames/issues/9) and remains unfixed.

- Signed installation and launch: confirmed by the owner using Sideloadly on
  Windows. Recheck the reported `apk` output shift after the combined 0.2.0 update.
- Cold launch/download and offline reopen the private Alpine shell; verify a
  failed initial install cannot replace an existing store.
- Type/select/copy Unicode and inspect true color with software and hardware
  keyboards; rotate/resize the window and check stty size and foreground SIGWINCH.
- Verify SSH fingerprint against an independent server fingerprint; test unknown,
  changed and known keys, wrong passwords, encrypted Ed25519 and Keychain deletion.
- Exercise SSH PTY/SFTP over IPv4/IPv6, localhost/LAN and Internet; check local
  network consent, Wi-Fi changes, cancellation and network outage errors.
- Import/export 1 MiB and larger files through On My iPad, iCloud Drive and at
  least one third-party provider; test collisions, unavailable providers and
  insufficient storage. Confirm no selected URL remains a live guest mount.
- Background/foreground the app, close a busy local shell, close SSH during
  connection/transfer, and confirm store locks and network sockets are released.
- Inspect memory and energy use with long output and up to eight terminal tabs.

The initial local stack failure from Alpine line editing is covered by the real
embedding integration test. Linux unprivileged OpenSSH cannot allocate a login
PTY in this container; its no-PTY variant verifies native auth/file transfer.
macOS CI runs the PTY variant with the runner's standard local test daemon.
